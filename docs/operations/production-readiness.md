## Go-live checklist (v1.0)

Self-hosted bundle:

1. Create the shop key and the offline master key once
   ([../LICENSE_KEY_OPERATIONS.md](../LICENSE_KEY_OPERATIONS.md)); commit both public keys to
   `PRODUCTION_PUBLIC_KEYS`; set `UPTIVORA_SIGNER_KEY_ID` on the hosted server. Licences are
   then signed and emailed automatically after payment.
2. Licence agreement (EULA) and purchase terms reviewed and published.
3. Version `1.0.0` in `backend/pyproject.toml`, `backend/app/core/config.py`,
   `frontend/package.json`; [CHANGELOG.md](../../CHANGELOG.md) dated; tag `v1.0.0`.
4. `deploy/release/build.sh` from the tag; smoke test on a fresh VM as in
   [release.md](release.md); publish the bundle and `SHA256SUMS`.

Hosted service:

1. Server per [vps-hardening.md](vps-hardening.md) and [firewall.md](firewall.md); deploy per
   [hosted-deployment.md](hosted-deployment.md).
2. `.env`: domain, SMTP (SPF/DKIM set up for the sending domain), canaries, heartbeat URL;
   `UPTIVORA_BILLING_PROVIDER=disabled` (plans assigned by the operator) until a provider
   exists — TEST MODE only on a separate staging domain.
3. `docker compose run --rm api python -m app.cli preflight --smtp` — no FAIL lines.
4. External uptime check of `https://<domain>/api/health/service` from another provider,
   and/or the heartbeat URL, alerting the operator by a channel that does not depend on this
   server (SMS, another email provider).
5. Off-site backup copy running; one restore performed on another machine and recorded.
6. Legal pages reviewed, operator details filled in, `LEGAL_STATUS.reviewed = true` (no draft
   banner on /terms, /privacy, /legal, /licence-agreement, /dpa).
7. Create the operator account (`python -m app.cli create-user --admin`), sign in, check
   Admin → System shows no issues.
8. Add a few real monitors (including one that is known to fail) and confirm the alert and
   recovery emails arrive.
